## 2. The two criticals

### INS-1 — filings are deadlocked and can never issue permits
`web/src/pages/officer/ReviewPage.tsx:689` early-returns the compact inspection box whenever
`app.status === 'for_inspection'`, keyed on the filing's status alone. Its own docblock at `:652`
still asserts the premise commit `5da4daa` deleted — that reaching `for_inspection` meant every review
was finished.

An office whose review is still `pending` therefore gets **no Approve or Return control anywhere**.
No approval → `scheduleInspectionFor` never fires → `isFullyCleared` never passes → permits are never
issued. `BIZ-2026-00958` has five offices in that state.

The API has no such block — `AssignmentController::approve` and `WorkflowService::approveAssignment`
carry no status guard. **The deadlock is purely client-side, which is why all 649 backend tests pass.**

### INS-5 — illegal transitions out of terminal states (unreported)
`WorkflowService::transition()` (`:34-50`) has no legality table, and `afterReviewProgress` is called
unconditionally at `:185`. Any office's approval drags a `returned`, `rejected` or `cancelled` filing
into `for_inspection`. The returned case is reachable through the UI and silently cancels the
applicant's revision request. **101 rejected filings currently carry a still-approvable assignment.**

Unreachable before `5da4daa` — the `$allDone` gate I deleted was incidentally blocking it.

## 4. Tests that currently *enforce* the bugs

This is the most dangerous thing in this audit. Two suites will **fail when the bug is fixed**, and
must be changed deliberately rather than "repaired":

- `web/e2e/inspection-review.spec.ts:173` asserts the review form is absent on **any** `for_inspection`
  filing, unconditionally — and its fixture can land on the very office whose review is pending. It
  locks INS-1 in.
- `web/e2e/clearances.spec.ts:608-647` asserts `getByRole('button', {name: /don't apply/i})` has count
  **0**. It enforces CLR-1. The test that would have caught the bug was deleted in the same commit.

Tests that pass while a bug is open:
- `api/tests/Feature/OfficeScopingTest.php:390` asserts the right thing about the **wrong endpoint**
  (`/office-forms`, not `/assignments/{id}`). `grep office_forms api/tests/` returns nothing.
- No e2e test ever uploads a file, so CLR-1's failing request is never sent.
- The insights "similar" test builds a neighbourhood where both keys happen to agree.
- No test asserts any of the four notice strings; deleting the banner turns nothing red.

## 5. Fix order and interference

Ordered so that no fix invalidates a later one.

**Phase 1 — stop the bleeding (independent, no collisions)**
1. `INS-5` — add a transition legality table. Touches `WorkflowService` only. Do first: every other
   workflow fix assumes transitions are legal.
2. `SEP-1` — filter office forms in the assignment payload. Server-side, `ApplicationResource`.
   Personal data.
3. `CLR-3` — stop `onApply` deleting an upload without confirmation.

**Phase 2 — the deadlock (single reconciliation, two clusters)**
4. `INS-1` + `SEP-3`/`SEP-4` share one rule: **the review form appears iff this office still owes a
   review.** They MUST be designed together — INS-1's fix restores a form the client twice asked to be
   removed, and SEP-3's issuance-date prefill reads the same array SEP-1 filters. Fixing SEP-1 alone
   leaves foreign offices with empty inputs and a live Save button.
   - Shared file `ReviewPage.tsx`: inspection territory is **646–735**, separability is **below 737**
     plus the banner at **971–992**. `sendRemark` (798–820) is used by both Reject and Return —
     coordinate before editing.
5. `INS-2` — retune the tab partition once (4) settles what each office sees.

**Phase 3 — clearances (depends on nothing above, but must not disturb assignment fixity)**
6. `CLR-1` + `CLR-2` together. `isFullyCleared` now depends solely on the assignment set, so a
   withdraw that detaches a permit type changes the denominator.
   - **Do not touch `isUnlocked`.** It is Draft-only, and that is the only reason auto-withdraw is
     safe: no assessment, no assignment, no permit exists yet. Unlocking `Returned`/`PendingPayment`
     and auto-detaching would strip a line from an issued Tax Order of Payment with **no refund path
     anywhere in the codebase**.
   - Any auto-withdraw must route through `unapply`'s three guards, especially `officeHasActed`.

**Phase 4 — presentation (no workflow risk)**
7. `INS-A1`/`A2`/`A3` — reconcile the two PSIC keys, or say on screen that they differ.
8. `WARN-1`/`WARN-2` — precompute the offered windows (the real fix) and then plain-word what remains.
   Keep `meta.source`/`engine` fields; PDFs keep engine naming, screens do not.
9. `SEP-5`/`SEP-6`/`SEP-7`, `INS-3`/`INS-4`/`INS-8`, `CLR-4`/`CLR-5`.
